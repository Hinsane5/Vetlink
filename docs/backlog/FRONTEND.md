# Backlog frontend / mobile Android

Status keseluruhan saat ini: **FE-00 Selesai, FE-01 Sedang dikerjakan, FE-02 Selesai, FE-03/04/05/06/07/08/09/10 Sedang dikerjakan**; FE-11–FE-25 **Belum mulai**. Tahap aktif mengikuti arahan pengguna: flow frontend tanpa autentikasi dan tanpa backend jaringan. Acceptance autentikasi FE-03 ditunda; implementasi historisnya tidak dipasang pada aplikasi aktif. Data fiktif lokal tetap dipakai agar screen dapat menampilkan perubahan yang konsisten.

Status setiap tiket: **Selesai** berarti seluruh acceptance criteria terpenuhi dan buktinya dicatat; **Sedang dikerjakan** berarti ada progres tetapi acceptance belum lengkap; **Belum mulai** berarti implementasi belum dimulai.

Setiap tiket harus menyertakan implementasi UI/domain/adapter lokal yang relevan, acceptance criteria, bukti pengujian sesuai risiko, dan dokumentasi status. “Frontend” di fase lokal mencakup use case dan repository lokal; tidak boleh menunggu backend untuk menjalankan flow. Acuan visual: [Figma mapping](../FIGMA_MAPPING.md), fungsi: [Features](../FEATURES.md).

## Definition of Done tiket

- Perilaku dan states acceptance di atas bekerja melalui data/use case, tanpa tombol testing dalam produk.
- Route/component Figma dipetakan, screenshot dibandingkan untuk layar yang berubah; selisih beralasan dicatat.
- Guard kritis mempunyai tes domain/repository yang bermakna; UI keyboard/back/scroll diperiksa di Android bila terpengaruh.
- Failure/retry tidak meninggalkan data setengah commit atau sukses palsu.
- Status backlog, README dan dokumentasi integrasi mencerminkan bukti nyata; jangan menandai semua fitur selesai hanya karena screen ada.

## Progres FE-09

UI booking terhubung dari profil dokter berdasarkan `vetId`: layanan, picker ternak milik Peternak dan species yang sesuai, tanggal/waktu proyeksi FE-08, keluhan, alamat wajib untuk kunjungan, picker foto/video pengguna, draft tersimpan dan review biaya. Kembali dari perubahan form menawarkan Simpan draft/Buang/Tetap mengedit. Draft parsial dapat dilanjutkan dari dokter yang sama setelah pembukaan ulang; perubahan teks harus disimpan sebelum menutup aplikasi. Slot dapat dimuat ulang tanpa mengganti input form.

`BookingService` memvalidasi ulang dokter verified/accepting, layanan/species, kepemilikan ternak/farm, slot aktual, lampiran dan tarif pada transaksi submit. Consultation `awaiting_payment`, quote snapshot, relasi dan penanda draft submitted ditulis atomik. `operationKey=booking:<draftId>` dan transaksi mencegah double submit; retry melalui service baru mengembalikan ID yang sama. Dua Peternak yang berebut slot hanya menghasilkan satu reservasi. Tidak ada payment succeeded, requested, chat aktif, atau janji diterima dari konfirmasi ini. Editor jadwal FE-11 serta pembayaran FE-19 masih belum dibuat; acceptance payment-success → requested belum dapat diuji.

Typecheck, lint dan 49 tes lulus, termasuk sembilan skenario booking menggunakan adapter SQLite riil in-memory. Export Android (740 modul) dan Gradle debug (24 menit 51 detik) lulus; APK dipasang di Xiaomi dan startup terbaru terbukti lewat screenshot. Rincian ada di [Testing](../TESTING.md). Tap Xiaomi masih ditolak MIUI; form, pilihan slot, picker, draft cold restart perangkat, keyboard/scroll/dialog/back, viewport kecil/font besar, dan pembandingan visual booking **belum diuji/terblokir**. FE-09 tetap Sedang dikerjakan. Figma node Booking nyata `12:2280` pada file utama terhalang izin edit; link terbaru terhalang kuota Starter.
