# Handover kontrak API untuk mobile

Status 19 November 2026: `EXPO_PUBLIC_API_BASE_URL` memilih ServerAuthFlow API saat startup; mode itu tidak membuka SQLite. Runtime default tetap SQLite, dan hanya subset layar yang sudah memakai API. Gunakan OpenAPI aktif di `/openapi.json` dan [kontrak integrasi](API_CONTRACT.md) sebagai sumber detail route/schema; tidak ada URL produksi yang dipilih.

## Koneksi dan sesi

Untuk development, API berjalan di `http://localhost:3000`; prefix route adalah `/v1`, sehingga endpoint kesehatan ada di `/v1/health/live` dan `/v1/health/ready`. Swagger UI tersedia di `/docs`. Jalankan backend mengikuti [README API](../apps/api/README.md) dengan PostgreSQL lokal dan nilai terbuka dari `.env.example`.

`POST /v1/auth/register` atau `POST /v1/auth/login` mengembalikan `accessToken`, `refreshToken`, `sessionId`, `activeRole`, dan user. Kirim token sebagai `Authorization: Bearer <accessToken>` pada setiap route terproteksi. `GET /v1/me` membaca identitas serta peran dari sesi, bukan dari ID atau klaim user yang dikirim client. Access token berlaku 15 menit; refresh token berotasi dan sesi berakhir dalam 30 hari. Logout dan refresh memakai refresh token sesuai schema OpenAPI.

Pergantian active role pada sesi yang sama memakai `POST /v1/auth/active-role` dengan body `{ "activeRole": "farmer" | "vet" }` dan bearer access token saat ini. Server memeriksa membership di PostgreSQL dalam transaksi, mempertahankan `sessionId` dan expiry absolut, lalu mengembalikan `AuthSessionResponse` dengan access/refresh token baru; token lama tidak lagi aktif. Jika membership tidak ada, server merespons 403 dan sesi/token tidak berubah. Ganti peran tidak membuka pasien atau transaksi pihak lain karena setiap route tetap memeriksa active role dan owner/assignment. Simpan ID resource di navigasi lalu baca ulang data terkini dari repository/API. Seorang Peternak dapat memiliki banyak Farm (DEC-27); daftar ternak dapat mencakup seluruh Farm milik akun, dan pembuatan ternak wajib mengirim `farmId` pilihan.

## Aturan request yang harus dipertahankan

- Gunakan UUID/ID resource yang dikembalikan API; jangan mengandalkan kode tampilan atau pasien default.
- Rupiah dikirim dan diterima sebagai integer `IDR`. Nominal payment/order dihitung backend dari quote/snapshot; `CreatePaymentDto` tidak menerima nominal.
- Timestamp request memakai ISO-8601 dengan zona waktu. Slot dan kalender mengikuti timezone Dokter; jangan menafsirkan waktu lokal sebagai UTC tanpa offset.
- Mutasi dengan `expectedVersion` harus memakai versi terbaru. `409` meminta client memuat ulang dan meninjau perubahan sebelum mencoba lagi.
- Untuk route yang menampilkan `Idempotency-Key` di OpenAPI, buat key 8–128 karakter per tindakan logis. Simpan key bersama request tertunda; retry request yang sama menggunakan key dan payload yang sama. Payload berbeda memerlukan tindakan baru dan key baru.
- `cursor` adalah opaque. Pertahankan persis nilai `nextCursor`; hentikan saat `hasMore=false`.
- Jangan menetapkan `verified`, `final`, `completed`, `paid`, atau saldo dari client. Ikuti action endpoint dan hasil yang disimpan server.

Envelope error memuat `{code, message, requestId}` dan dapat memuat `fieldErrors`. Peta respons untuk client: `400` input tidak valid, `401` sesi/token, `403` role, `404` resource tidak dapat diakses/ada, `409` konflik versi/status/idempotensi, `413` file terlalu besar, `422` aturan domain atau saldo, `429` pembatasan request, dan `503` layanan/adapter gagal. Untuk `409`/`503`, baca ulang status sebelum retry; jangan tampilkan keberhasilan yang belum tersimpan.

## Baca katalog produk FE-25

Adapter read-only `CatalogReadRepository` memanggil `GET /v1/products` dan `GET /v1/products/{id}`. Pencarian memakai query backend `name`, `category`, `species`, `minPrice`, `maxPrice`, `cursor`, dan `limit`; harga minimum/maksimum dikirim sebagai integer rupiah. Response halaman berbentuk `{items, nextCursor, hasMore}` dengan produk `{id, name, category, species, description, unitPriceIdr, imageAttachmentId, active}`. Adapter memvalidasi UUID server, produk aktif, spesies domain, nullable attachment, struktur cursor, dan harga rupiah aman sebelum memetakan harga ke `CatalogProduct.unitPrice`/`currency: IDR`.

Cursor adalah nilai opaque dari server: pertahankan persis `nextCursor` untuk request berikutnya dan hentikan saat `hasMore=false`. Jangan menghitung cursor, menyortir ulang, atau mengganti ID dengan kode tampilan. Akses katalog menggunakan bearer/session role server; jangan mengirim `ownerId`. Detail produk tidak dikenal/nonaktif menghasilkan 404 melalui error envelope.

Farm/address, ternak/pasien, dan direktori/slot Dokter memiliki kontrak respons eksplisit pada backend. Port dan adapter baca mobile untuk route itu tersedia di `apps/mobile/src/application/ports` dan `apps/mobile/src/data/remote`; semuanya memakai bearer session. Adapter tidak meminta `ownerId`: scope Farm/alamat, ternak Peternak atau pasien Dokter, serta direktori Dokter verified tetap ditentukan backend. Mode API memakai sebagian repository read/write tersebut di UI; runtime default masih SQLite.

## Read Farm, address, ternak, dan direktori

`GET /v1/me/farms` dan `GET /v1/me/addresses` mengembalikan array camelCase milik Peternak aktif. `GET /v1/me/farms/{id}` dan `GET /v1/me/addresses/{id}` membaca detail saat diperlukan; akun lain mendapat 404 dan peran Dokter mendapat 403. DTO menyertakan `id`, field domain, `createdAt`, `updatedAt`, dan `version`; owner ID tidak dikirim. `location` Farm dapat `null`. Koordinat address dan `weightKg` ternak adalah string decimal PostgreSQL untuk menjaga presisi; timestamp adalah ISO-8601 UTC.

`FarmReadRepository`/`HttpApiFarmReadRepository` menyediakan `listFarms`, `getFarmById`, `listAddresses`, dan `getAddressById`. `LivestockReadRepository`/`HttpApiLivestockReadRepository` menyediakan `listPage` dan `getById`; `VetDirectoryReadRepository`/`HttpApiVetDirectoryReadRepository` menyediakan `search`, `getById`, dan `getSlots`. Tipe read API menyimpan DTO backend tanpa menggabungkannya ke snapshot SQLite; koordinat dan berat decimal tetap string.

Mode API juga memakai `FarmWriteRepository` untuk menambah/mengubah alamat, serta PATCH Farm dengan `expectedVersion` untuk memilih alamat kunjungan. Alamat dibuat tanpa mengirim owner ID dan hanya Peternak dapat mengubahnya. Booking visit mengambil `visitAddressId` dari Farm dan mencocokkan snapshot quote dengan alamat yang sama. Bila hasil POST/PATCH tidak pasti, UI membaca ulang daftar/versi sebelum menyediakan percobaan berikutnya.

`GET /v1/livestock` dan `GET /v1/vets` mempertahankan respons array lama. Untuk daftar besar gunakan route additive `GET /v1/livestock/page?limit=50` dan `GET /v1/vets/page?name=...&service=...&limit=50`; halaman memakai `{items,nextCursor,hasMore}`. Ternak Peternak diurutkan `createdAt DESC,id ASC`; Dokter hanya melihat ternak yang terkait layanan miliknya dan tidak melihat record draft/awaiting-payment. Direktori hanya berisi Dokter verified dengan availability/tarif, diurutkan `professionalName` lowercase lalu ID. Filter directory dapat dipakai bersama pagination.

Jangan mengurai atau membuat cursor sendiri: salin `nextCursor` persis, kirim hanya ke route/scope yang sama, dan berhenti saat `hasMore=false`. Cursor ternak terikat ke user + active role; cursor direktori terikat ke filter. `limit` default 20 dan maksimum 100. API tidak memberi snapshot lintas halaman, sehingga insert/delete yang terjadi selama pagination dapat mengubah isi daftar. Direktori mengembalikan `fees`, `minFeeIdr`, dan `maxFeeIdr` sebagai JSON integer IDR yang aman; detail Dokter memuat object tarif `rates` dan durasi layanan. `GET /v1/vets/{id}/slots` adalah array berisi hanya `startsAt` dan `endsAt` timestamp ISO-8601, bukan ID slot atau reservasi.

Adapter memvalidasi UUID sebelum detail request dan memeriksa DTO response sebelum mengembalikan record: enum species/service, nullable decimal address/weight, timestamp UTC, versi dan batas durasi, tarif sebagai safe integer IDR, serta struktur halaman. Cursor opaque dibatasi 512 karakter dan diteruskan tanpa trim atau decode. Query direktori mengikuti batas DTO (`name`/`location` 120 karakter, tarif integer IDR aman, `limit` 1–100); rentang slot harus berupa tanggal valid berurutan dengan selisih maksimal 31 hari (32 tanggal inklusif), sesuai aturan server. Respons detail dokter tetap bersifat discoverable/verified karena route server yang menyaringnya; aksi layanan tetap wajib melewati guard server.

## Write Farm/alamat dan ternak FE-25

`FarmWriteRepository`/`HttpApiFarmWriteRepository` mengirim `POST /v1/me/farms`, `PATCH /v1/me/farms/{id}`, `POST /v1/me/addresses`, `PATCH /v1/me/addresses/{id}`, dan `DELETE /v1/me/addresses/{id}`. BE-02 belum memiliki DELETE Farm. Farm memakai UUID `visitAddressId` opsional dan daftar spesies domain opsional (maksimal seluruh enum, tanpa duplikat; daftar kosong berarti tidak membatasi spesies); nama dibatasi 120 karakter, timezone 80 karakter, dan object `location` dibatasi 64 KiB pada adapter. PATCH Farm menyertakan `expectedVersion` positive safe integer.

Address POST/PATCH mengirim field alamat dengan batas BE-02; PATCH menyertakan `expectedVersion`. Latitude/longitude dikirim sebagai JSON number, harus dikirim berpasangan, berada dalam rentang −90…90/−180…180 dan maksimal enam desimal. Read DTO mengembalikan string decimal PostgreSQL; parser memeriksa format, rentang, serta pasangan null. DELETE menunggu `{ "deleted": true }` sebelum resolve.

`LivestockWriteRepository`/`HttpApiLivestockWriteRepository` mengirim `POST /v1/livestock` dan `PATCH /v1/livestock/{id}`. Create mewajibkan `farmId` UUID karena satu Peternak dapat memiliki banyak Farm; tidak ada `ownerId` atau `farmerId` di request. Bearer session memberi actor, sedangkan active-role, membership, kepemilikan Farm, kecocokan species, dan akses pasien diperiksa server. `displayCode` maksimal 32 karakter, nama 120, ras 80, species/sex memakai enum domain, umur 0–1200 bulan, dan tanggal memakai format `YYYY-MM-DD`; tanggal lahir dan estimasi umur tidak dikirim bersama. `weightKg` adalah JSON number maksimal dua desimal dan dibatasi sesuai `numeric(8,2)`, sedangkan response tetap decimal string. PATCH mewajibkan `expectedVersion` safe integer dan minimal satu field perubahan. Adapter memvalidasi DTO hasil POST/PATCH dengan parser yang sama seperti read adapter dan meneruskan envelope HTTP 403/404/409/422 sebagai error domain; error tidak membuat hasil lokal. Route DELETE ternak dan care-event tidak termasuk slice adapter ini.

Untuk recovery Payment setelah install ulang, response hilang, atau pindah perangkat, baca `GET /v1/payments?payableType=consultation&payableId=<id>` (atau `payableType=order`) memakai payable ID dari API. Route ini mengembalikan Payment owner saja; 404 berarti Payment belum ada atau tidak dimiliki. Setelah mendapatkan Payment ID, `GET /v1/payments/{id}` memuat status Payment, Attempt terbaru, dan seluruh `attempts[]`; `GET /v1/payments/{id}/attempts` membaca histori Attempt saja. Jangan kirim ulang pembayaran dengan status `pending`/`succeeded`; setelah status tersimpan `failed`, gunakan payable dan Payment yang sama dengan Idempotency-Key baru. Setiap Attempt memuat nomor urut, status, referensi adapter, dan waktu percobaan; nominal tetap integer IDR dari snapshot server.

Detail field, status, dan error ada di [OpenAPI](../apps/api/README.md#batas-openapi-be-0016) dan [kontrak API](API_CONTRACT.md). Pembayaran/order memakai Payment yang sama pada retry; withdrawal punya satu reservasi per operasi. Adapter lokal dapat mengembalikan `pending`, `succeeded`, atau `failed`; respons mengikuti hasil yang benar-benar tersimpan.

## Sesi lintas perangkat dan batas integrasi

Backend membaca data dari PostgreSQL yang sama untuk sesi terpisah milik akun yang sama. `api:smoke` menguji switch role hanya setelah membership ada, rotasi token tanpa mengubah session ID/expiry, dan penolakan akses ke pasien yang tidak terkait. Untuk payment, satu sesi membuat Payment pada konsultasi hewan dari Farm kedua; sesi kedua membaca status/Attempt, melihat status `failed`, retry dengan key baru pada Payment yang sama, lalu kedua sesi membaca status dan histori dari database. Pembayaran paralel dengan key sama dan withdrawal paralel dengan key sama tetap diuji; hasilnya berbagi record tanpa menggandakan Attempt/reservasi. Ini membuktikan kontrak API lintas sesi, bukan QA UI pada dua perangkat fisik.

Storage SQLite tetap menjadi runtime default per instalasi. Jika `EXPO_PUBLIC_API_BASE_URL` diatur, startup memilih ServerAuthFlow yang membaca/menulis subset layar melalui API dan tidak membuka SQLite. Layar layanan lain masih memakai runtime lokal default; jangan gabungkan sumber data pada satu flow. Offline sync produksi tidak termasuk, dan tampilan dua perangkat belum diuji. Saat adapter layar lain dipindahkan, gunakan satu sumber tulis aktif pada satu waktu.

Semua hasil layanan pada milestone ini lokal/fiktif. Payment adapter aktif mengembalikan `pending`; tidak ada provider pembayaran/kurir/notifikasi/payout produksi, callback finansial publik, kredensial produksi, deployment, atau transaksi uang nyata. Jangan mengartikan referensi lokal sebagai transaksi nyata.

## FE-25 baca riwayat kesehatan, care-event, dan pasien BE-03

`HttpApiLivestockHealthRepository` memanggil `GET /v1/livestock/{id}/health-events` dan membaca respons array langsung dari `LivestockService.timeline`, bukan envelope `{items}`. OpenAPI mendeklarasikan `LivestockHealthEventResponseDto` dengan tepat enam field: `id`, `kind`, `occurredAt`, `description`, `provenance`, dan `createdAt`; parser mempertahankan urutan server serta memvalidasi UUID, enum kind/provenance, dan timestamp UTC. `provenance=clinical_note` berasal dari catatan final immutable Dokter, `farmer_report` adalah laporan Peternak, dan `reminder` adalah event perawatan. Draft klinis tidak dipublikasikan oleh service timeline. Projection tidak memberikan actor, field internal clinical note, atau attachment.

`POST /v1/livestock/{id}/care-events` menerima `{kind,occurredAt,description,sourceKey}`. Adapter hanya menerima kind `disease|vaccine|medication|care`, timestamp ISO-8601 dengan zona waktu, deskripsi 1–2.000 karakter, dan `sourceKey` 8–128 karakter. Source key di body adalah kontrak idempotensi aktual; jangan menggantinya dengan header `Idempotency-Key`. Kirim ulang key dan payload yang sama untuk mengambil event tersimpan yang sama setelah response hilang; key sama dengan payload berbeda ditolak server sebagai konflik. `ApiClient` tidak mengulang POST otomatis pada kegagalan jaringan dan adapter tidak mengarang hasil sukses. Saat hasil belum diketahui, jangan tampilkan sukses; retry manual dengan source key dan payload persis sama.

Route care-event hanya Peternak: controller memakai `@RequireRoles('farmer')` dan service mengulang `requireFarmer`; owner ternak dan actor berasal dari bearer server. Adapter mengirim ID ternak di path dan allowlist empat field body, tanpa `ownerId`, `farmerId`, `actorId`, atau `provenance`. Hasil POST `CareEventResponseDto` aktual hanya `id`, `kind`, `occurredAt`, `description`, dan `provenance=farmer_report`; tidak ada `createdAt` atau `sourceKey`. Source key tetap berada di body sebagai identitas idempotensi; jangan menggantinya dengan header `Idempotency-Key`. Retry dengan key/payload sama mengembalikan event tersimpan yang sama; key sama dengan payload berbeda mendapat 409. Karena itu response API disimpan sebagai model terpisah dan belum dipetakan ke `HealthRecordSnapshot`; jangan menyimpulkan laporan Peternak sebagai catatan final Dokter.

`GET /v1/patients` mengembalikan array `PatientResponseDto` dengan field compact (`id`, `displayCode`, `name`, `species`, `breed`, `sex`, `birthDate`, `estimatedAgeMonths`, `weightKg`, `farmId`, `farmerId`) serta `ownerName`, `lastServiceAt`, `serviceCount`, `latestServiceType`, dan `latestServiceStatus`. Adapter mobile memvalidasi dan mempertahankan field tersebut; status visit yang berjalan memakai tahap `en_route`/`arrived`/`examining`. Semua nilai berasal dari konsultasi pada pasangan pasien/pemilik yang ditugaskan kepada Dokter di bearer, dengan `draft` dan `awaiting_payment` dikecualikan. `weightKg` tetap decimal string PostgreSQL. Route tidak mengekspos email/kontak atau foto privat seperti `PatientSnapshot`. UI mode API memeriksa membership ID terhadap daftar `/patients` sebelum meminta `GET /livestock/{id}/health-events`; backend memeriksa assignment kembali. Timeline hanya berisi projection event dan catatan klinis final, bukan draft, attachment, atau temuan klinis lengkap. `App.tsx` tetap memilih SQLite pada runtime default, sedangkan ServerAuthFlow API terpisah tidak membuka SQLite; tidak ada dual-write.

## Proyeksi respons Consultation untuk FE-25 Flow A/B

OpenAPI response consultation sekarang mengikuti shape dari service BE-05. `POST /v1/consultation-quotes` memberi `ConsultationQuoteResponseDto` (201), termasuk IDR integer aman (`feeIdr`, `commissionIdr`, `amountIdr`) dan `visitAddressSnapshot` null untuk chat. Booking (`POST /v1/consultations`, 201) serta action accept/reject/start/complete (200) memberi `{operationId, replayed, consultation}` setelah hasil tersimpan. Proposal jadwal menambah `proposalId` atau `decision`; action Visit menambah `visit` dengan stage dan waktu transisi.

Daftar adalah array dengan projection `completedAt`; detail memakai `completionAt` untuk Consultation dan `visitCompletedAt` untuk Visit; GET `/consultations/{id}/visit` memiliki `completedAt` serta `updatedAt`. Pertahankan pemetaan field per route karena nama-nama ini merefleksikan query service berbeda. `feeIdr` dan `commissionIdr` pada Consultation list/detail tetap berupa string bigint demi kompatibilitas; gunakan field additive `feeAmountIdr` dan `commissionAmountIdr` sebagai integer IDR safe integer. Field quote tetap integer `feeIdr`, `commissionIdr`, dan `amountIdr`. Detail/list mematuhi scope Peternak owner atau Dokter assigned; Dokter tidak menerima `awaiting_payment`. Aksi Visit mengikuti urutan server, dan completion tetap mensyaratkan catatan final, status layanan yang sesuai, pembayaran cocok, konfirmasi, serta Visit `examining` untuk kunjungan. API contract tests mengunci route response schema, alias integer IDR, dan batas safe integer; runtime mobile tetap SQLite sampai perpindahan sumber baca/tulis terkoordinasi.

Port `ApiConsultationRepository` dan `HttpApiConsultationRepository` menyediakan quote, create booking, list, detail, dan detail Visit sebagai model API terpisah. Quote mengirim allowlist `vetId`, `animalId`, `serviceType`, `startsAt`, `complaint`, dan `addressId` hanya bila diberikan; layanan `visit` mewajibkan alamat UUID eksplisit. Booking hanya mengirim `quoteId`; ID resource divalidasi sebagai UUID dan nilai ID server dipertahankan persis. Tidak ada `ownerId`, `farmerId`, tarif, atau komisi di payload tulis; scope pemilik/assignment berasal dari bearer server.

Kedua POST menerima satu operasi berisi `Idempotency-Key` 8–128 karakter dan payload tetap. Bila hasil transport belum diketahui, adapter gagal tanpa hasil lokal dan tidak mengulang request otomatis; retry manual harus memakai operasi, key, dan payload yang sama. Jangan membuat quote/booking kedua untuk memulihkan hasil yang belum diketahui. Timestamp harus ISO-8601 dengan `Z` atau offset eksplisit; keluhan 1–4.000 karakter; response DTO, snapshot alamat, dan integer IDR safe divalidasi sebelum dikembalikan. ServerAuthFlow API kini memakai repository quote/booking untuk UI; tes lokal memeriksa service dengan fake repository, sedangkan API server hidup dan QA dua perangkat masih belum dilakukan.

Adapter yang sama kini menyediakan aksi BE-05: `accept`, `reject`, `proposeSchedule`, `respondScheduleProposal`, `startChat`, `advanceVisit` (`depart`, `arrive`, `start-examination`), dan `complete`. Setiap POST memakai UUID konsultasi/proposal, `expectedVersion` positif, `Idempotency-Key` caller yang stabil, serta allowlist body. Transisi Visit juga membawa `expectedVisitVersion`; completion membutuhkan `confirmation: true` dan versi Visit bila terkait. Server tetap memutuskan role, status, pembayaran, verifikasi Dokter, catatan final, dan urutan transisi. Adapter tidak menaikkan status secara lokal, tidak mengulang otomatis, dan tidak menyatakan sukses sebelum respons tersimpan lolos parsing.

Pada replay idempoten, implementasi BE-05 mengembalikan `{operationId,replayed:true,consultation}` tanpa field tambahan `proposalId`, `decision`, atau `visit` yang ada pada respons baru. Port menandai tambahan itu opsional; setelah replay, caller perlu membaca detail/Visit berdasarkan ID konsultasi dari hasil. UI masih memakai SQLite, sehingga aksi ini belum tersedia pada runtime API mobile. Integrasi satu otoritas dan QA fisik dua peran tetap gate FE-25.

## FE-25 pendapatan dan pencairan BE-15 Flow D

`HttpApiEarningsRepository` memakai `GET /v1/me/vet/earnings`, detail transaksi, daftar tujuan, daftar/detail withdrawal, dan `POST /v1/me/vet/withdrawals`. Scope Dokter diperoleh dari bearer server; tidak ada `vetId`/nominal hasil hitung client pada query atau hasil. Baca ringkasan memvalidasi saldo dan total integer rupiah aman, persamaan kotor dikurangi komisi, transaksi dan withdrawal, periode, serta cursor opak. Query memakai periode `YYYY-MM` atau rentang tanggal valid, limit maksimum 100. Status `submitting` berarti permintaan masih dalam proses adapter, `submitted` hanya berarti pengajuan diterima; keduanya bukan dana diterima.

POST mengirim hanya `{amount,destinationId}` dengan jumlah integer positif aman dan UUID tujuan. `Idempotency-Key` 8–128 karakter harus tetap sama untuk retry atas hasil transport yang belum diketahui; adapter tidak mengulang otomatis atau membuat status lokal. Respons dicocokkan dengan jumlah, tujuan, operation ID, serta outcome yang tersimpan. BE-15 tetap menggunakan adapter pencairan lokal/fiktif. Tidak ada transfer dana nyata atau provider produksi. Repository hanya diekspos melalui factory; runtime UI dan ledger mobile tetap SQLite sampai migrasi satu sumber yang lengkap.

## FE-25 availability dan kalender Dokter BE-04 Flow C

`HttpApiVetScheduleRepository` memakai `GET/PUT /v1/me/vet/availability`, `GET/POST /v1/me/vet/blocked-times`, `PUT/DELETE /v1/me/vet/blocked-times/{id}`, serta `GET /v1/me/vet/schedule`. GET availability mengembalikan row PostgreSQL dengan field `vet_id`, `weekday_rules`, `updated_at`, dan field profil/rates camelCase; parser mengubahnya menjadi model API mobile tersendiri. PUT mengirim hanya field DTO BE-04, `expectedVersion`, layanan, timezone IANA, aturan weekday, durasi, tarif integer rupiah, dan metadata profil opsional. Hasil PUT memuat `operationId`, `status=succeeded`, `occurredAt`, dan row availability tersimpan. Server tetap memeriksa verifikasi, konflik slot/booking, serta pemilik jadwal.

Kalender GET memakai rentang ISO-8601 dengan zona waktu, maksimum 32 hari, dan mengembalikan appointment, follow-up terjadwal, serta blok aktif dari server. `feeIdr` pada appointment tetap string bigint legacy; parser menolak nilai di atas safe integer tanpa mengubah kontrak. ## FE-25 catatan klinis dan rekomendasi BE-08

`HttpApiClinicalRepository` memakai GET/PUT `/v1/consultations/{id}/note`, POST `.../note/finalize`, GET/PUT `.../recommendation`, dan POST `.../recommendation/send`. Draft catatan sintetis dari GET Dokter belum mempunyai ID; row tersimpan memakai `consultation_id`, `care_instructions`, dan `finalized_at`. Adapter menormalkan keduanya ke model API dengan `id: null` hanya untuk draft yang belum tersimpan. Catatan final tetap hanya baca dan finalisasi tidak menyelesaikan layanan. Simpan/finalisasi membutuhkan versi positif dan dibatasi server pada Dokter assigned serta status layanan yang sesuai.

Model API memakai `items: null` pada hasil send untuk menandai bahwa daftar belum dimuat; caller harus GET lagi sebelum menampilkan daftar. ## FE-25 chat polling BE-07

`HttpApiChatRepository` memakai GET/POST `/v1/consultations/{id}/messages` serta POST `/v1/consultations/{id}/messages/{messageId}/retry`. GET memakai `limit` 1–100 dan cursor opak; item dalam tiap halaman berurutan lama-ke-baru. Respons menyimpan sender ID server, teks, lampiran, status delivery `pending/sent/failed`, attempt, dan timestamp. Penerima hanya memperoleh pesan `sent`; pengirim dapat membaca pending/failed. Parser menolak URL media selain path privat `/v1/attachments/{id}/content`, MIME tidak cocok, ukuran tidak aman, dan ID tidak valid.

POST mengirim `clientMessageId` UUID bersama teks sampai 4.000 karakter dan/atau maksimal lima ID lampiran committed. ID itu adalah identitas idempotensi BE-07; tidak ada header `Idempotency-Key` pada route pesan. Setelah respons hilang, baca ulang pesan atau ulangi payload persis sama dengan `clientMessageId` yang sama. Route retry menerima messageId record yang sudah diketahui dan tidak membuat record baru. Adapter tidak mengulang otomatis dan tidak menganggap status `pending` sebagai terkirim. Runtime UI tetap SQLite.

`HttpApiMediaRepository` memakai POST multipart `/v1/attachments/uploads` dengan `consultationId`, file URI lokal, dan `Idempotency-Key` stabil. Adapter membatasi JPEG/PNG/WebP 10 MiB dan MP4 50 MiB sebelum upload; server kembali memeriksa signature, akses konsultasi, serta batas konfigurasi. Respons `uploaded` belum boleh dipasang ke pesan; POST `/v1/attachments/{id}/commit` harus mengembalikan `committed`. GET metadata dan GET `/content` memakai bearer yang sama, termasuk refresh sesi sekali saat 401; URL relatif privat tidak boleh ditampilkan sebagai URL publik. Unduhan mengembalikan `ArrayBuffer` dan memeriksa jumlah byte terhadap metadata, sehingga caller harus mengelola memori dan penyimpanan berkas perangkat sebelum integrasi UI. Upload yang hasilnya tidak pasti tidak diulang otomatis; baca metadata bila ID diketahui atau ulangi file yang sama dengan key yang sama. Belum ada bukti transfer multipart/biner pada Android fisik atau integrasi UI API.
